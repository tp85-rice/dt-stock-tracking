Why some jobs need the Terminal

The project has three places where things happen. Only one of them is allowed to hold the database password and run the project's scripts on request, and that is a computer you control.

The website

Reads the data and lets you approve readings on /review. It never holds the database password, so it cannot load a whole spreadsheet. That is on purpose: a website that could rewrite the database would be the easiest thing to attack.

GitHub Actions

Runs the scheduled jobs (daily feeds, chart data, database updates, backups) with the password stored as a GitHub secret. Good for jobs that run on a timer or with a button.

Your Mac (Terminal)

Runs the jobs you start by hand with a file on your computer, like importing a driver sheet. The password lives in a file called .env that never leaves your Mac.

Why Claude does not run these for you: Claude works in a cloud copy of the code that does not have the database password, also on purpose. Claude prepares the files and the exact commands; you run the ones that write to the real database. This keeps a person in charge of every change to live data.

The Terminal in five minutes

The Terminal is a window where you type a command and press Return. It answers in text. Your Mac shows a prompt ending in %, like thaophan818@Thaos-MacBook-Pro dt-stock-tracking %. The word before % is the folder you are in.

You see or typeMeaning
%Ready for your command. In this guide the grey boxes start with %; do not type it, the Copy button leaves it out.
(.venv) at the startThe project's own Python is switched on. You need it for every project command.
(base) at the startAnaconda's Python is also around. Harmless; ignore it.
cd ~/dt-stock-trackingGo to the project folder (~ is your home folder).
ls / pwdList the files here / show which folder you are in.
open inputsOpen a folder in Finder (or a file in its app).
↑Bring back the previous command.
TabFinish a file name for you.
Ctrl+CStop whatever is running. Always safe; an import stopped half-way writes nothing.
clearClean the screen.
One box at a timePaste one grey box, press Return, wait for the % to come back, read the last lines, then do the next box. If anything looks unexpected, copy the output into the chat with Claude.

A. One-time setup on your Mac

You did most of this on Nov 5. Repeat it only on a new Mac, for Duong, or if the project folder was deleted.

  1. Open Terminal: ⌘+Space, type Terminal, press Return.
  2. Check Python is 3.12 or newer: 
    python3 --version
    If it says "command not found" or an older version, install Python from python.org (the macOS installer), then open a new Terminal window.
  3. Get the code (skip if ~/dt-stock-tracking already exists). The repo is private, so GitHub asks you to sign in: 
    git clone https://github.com/tp85-rice/dt-stock-tracking.git ~/dt-stock-tracking
  4. Go into the folder: 
    cd ~/dt-stock-tracking
  5. Create the project's own Python (once per folder): 
    python3 -m venv .venv
  6. Switch it on: 
    source .venv/bin/activate
    The prompt now starts with (.venv).
  7. Install the packages the scripts need: 
    pip install -r worker/requirements-dev.txt
  8. Create your private settings file and open it: 
    cp .env.example .env
    open -e .env
    On the DATABASE_URL= line, paste the Supabase connection string: Supabase › your project › Connect › Session pooler, with your database password in place of [YOUR-PASSWORD]. Save and close TextEdit.
  9. Check the connection: 
    python -c "from worker.db import connect; connect().close(); print('connected')"
    Expected
    connected
The .env file is a passwordNever paste its contents into the chat, an email, GitHub or a screenshot. Git ignores it, so it is never uploaded.

B. Start of every session

Do these four boxes every time you open a new Terminal window for the project. They put you in the folder, switch on the project's Python, and fetch Claude's latest files.

cd ~/dt-stock-tracking
source .venv/bin/activate
git checkout main
git pull
Expected (last line)
Already up to date.      (or a list of changed files)

If the list of changed files includes worker/requirements.txt, also run:

pip install -r worker/requirements-dev.txt

C. Jobs today

C1. Import a driver sheet Terminal

Use this when Claude says a sheet is ready, for example GRAB now. Do B first. Replace GRAB with the ticker.

  1. Check the sheet without touching the database: 
    python -m worker.import_xlsx inputs/GRAB_driver_sheet.xlsx --dry-run
    Expected (last lines)
    GRAB: 6 drivers, 26 signals, 29 base case rows, 19 event steps, 14 sources, 74 observations

Dry run: the sheet is valid. Nothing was written.
    Lines starting [WARNING] are information (for GRAB: older history rows with no base case, a few sources with no link, and D1 with six signals; all expected). Lines starting [ERROR] mean stop and send the output to Claude.
  2. Import it for real: 
    python -m worker.import_xlsx inputs/GRAB_driver_sheet.xlsx
    Expected (last line)
    Imported GRAB.
  3. Open the website, sign in, and check the ticker appears with its drivers and colours.
All or nothingAn import either finishes completely or writes nothing. If it stops with "Import stopped, nothing was written", the live site is unchanged.

C2. Re-import after Claude updates a sheet Terminal

Use this after Claude refreshes a sheet (NVDA after the Nov 17 results, a GRAB threshold Duong changes). It is the same as C1, after git pull fetched the new file.

  • Readings that came from the sheet are replaced by the sheet's. Readings you approved on /review are never touched.
  • Drivers, signals, sources and milestones are updated. Rows removed from the sheet are listed, not deleted.
  • Base case rows can never change. If a value changed, the import stops with "Base cases can't be changed: add it as a new version". Nothing is written; ask Claude for a new version (v2).

C3. Try a sheet as a hidden test ticker Terminal

Use this when you want to see a sheet in the database without anyone else seeing it.

python -m worker.import_xlsx inputs/GRAB_driver_sheet.xlsx --ticker TEST --test

Look at it in Supabase › SQL Editor with select * from v_scores where ticker = 'TEST';. Remove it afterwards in the same editor with select app.delete_test_ticker('TEST');.

C4. Look at a sheet Terminal

open inputs/GRAB_driver_sheet.xlsx

Excel opens it and the formula columns (colour, variance) calculate. Close it without saving. The sheets are written from research/<TICKER>/driver_spec.json, so hand edits would be lost and would block the next git pull. To change something, tell Claude.

C5. Feeds, chart data and backups GitHub Actions

These run on GitHub, not in the Terminal. To run one now: GitHub › tp85-rice/dt-stock-tracking › Actions › pick the job › Run workflow.

Job (Actions name)When it runsRun it by hand when
daily feedsEvery day 22:23 UTCA filing just came out and you don't want to wait. Tick "dry run" to only see what it would find.
weekly database backupMondaysBefore any big change. The backup file is under the run › Artifacts.

The Terminal can run the same jobs if GitHub is down, as a dry run that writes nothing:

D. Jobs later

D1. A new ticker Claude then Terminal

  1. Ask Claude to build the sheet (from research, or from your own base case file, as for GRAB).
  2. Claude opens a pull request, merges it, and lists decisions for you in research/OPEN_DECISIONS.md.
  3. Answer the decisions in chat. Claude updates the sheet.
  4. Do B, then C1 with the new ticker's file name.

D2. Base case after earnings Claude then Terminal

After a results call, ask Claude to refresh the sheet ("Refresh NVDA driver sheet"). Claude adds a new base case version (v2) with the consensus quoted in news coverage. Then do B and C1. New readings from the 10-Q also arrive on /review through the daily feeds; approve them there.

D3. AI agents (M5) Terminal

Once Duong's gold set is in the scorecard and an agent produces an answers file (Claude will say where), add your Anthropic key and daily spending cap to .env (open -e .env): ANTHROPIC_API_KEY=... and AGENT_DAILY_USD_CAP=1.00.

Score the agent against the gold set (writes a scored copy; the scorecard itself is not changed):

python -m worker.agents.evaluate templates/llm_eval_scorecard.xlsx answers.jsonl --version junior-v0.1 --out scored.xlsx
Expected (last line)
Result: PASS      (or FAIL, with the rates above it)

See what it would send to the review queue, then send it:

python -m worker.agents.submit answers.jsonl --dry-run
python -m worker.agents.submit answers.jsonl

Answers that fail the quote check are held back, never shown as pending. Everything else waits for you on /review.

D4. The database password changed

  1. Copy the new Session pooler string from Supabase › Connect.
  2. Update .env on your Mac (open -e .env, replace the DATABASE_URL line, save).
  3. Update the GitHub secret: repo › Settings › Secrets and variables › Actions › SUPABASE_DB_URL › Update.
  4. Check with the last box of A.

D5. A new Mac, or setting up Duong

Follow A from the start. Duong uses the same commands with his own folder; he needs collaborator access on GitHub and the connection string from an owner, shared in person or through a password manager, never by email or chat.

D6. Preview the website on your Mac (optional)

Only for looking at a design change before it goes live. Needs Node.js (the LTS version from nodejs.org). Uses sample data, never the database.

cd ~/dt-stock-tracking/web
npm install
npm run dev:fixtures

Open http://localhost:3000/t/NVDA in your browser. Stop it with Ctrl+C, then cd .. to go back.

F. Safety rules

  • Run --dry-run first whenever a command has one.
  • Never paste the contents of .env, a connection string or a password anywhere. Claude never needs them.
  • Don't run database changes (migrations) by hand; GitHub does it after review.
  • Don't edit files in the project folder by hand; ask Claude, so the change is reviewed and recorded.
  • Ctrl+C is always safe.
